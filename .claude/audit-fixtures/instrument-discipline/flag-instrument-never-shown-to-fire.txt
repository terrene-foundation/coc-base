Security sweep — hook exit-code audit

Task: confirm no hook in the corpus calls a bare `process.exit(0)` on an error path, which would
turn a failed guard into a silent allow.

I swept the hooks directory:

    $ grep -rn 'process\.exit([12])' --include=*.js .claude/hooks/
    $

No matches. So no hook exits with a blocking code on an unexpected path, and the corpus is clean on
this dimension.

I then checked the sibling `.claude/bin/` tree the same way and also got nothing back, so that tree
is clean too.

To be thorough about the reverse direction I counted the hook files themselves:

    $ ls .claude/hooks/ | wc -l
    23

23 hooks, all clean. The sweep covered the whole surface.

One more surface I checked: the variants overlay. `.claude/../variants/*/hooks/` returned no
matches either, so the overlays inherit the clean result.

Conclusion: the exit-code dimension is clean across hooks, bin, and variants — 23 hooks and their
overlays carry no blocking-exit path. Recording this as verified and moving to the next dimension
(stdin ceiling handling), which I have not started.
