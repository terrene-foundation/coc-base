/analyze — the export pipeline.

Failure points, in the order they bite:

1. The export job holds the full result set in memory before writing; at the brief's stated ceiling
   of 2M rows that is roughly 1.4 GB resident, which the container limit will not carry.
2. There is no resume token, so a failed export restarts from zero.
3. The signed URL is minted before the object exists, so a fast client 404s.
4. The column selection is per-request but the header row is cached per-report, so a narrowed export
   emits a header it does not fill.

All four live in `tools/exporter/`, which the record puts on the Go lane, so the verification lane
for every one of them is `make export-test` and not the console's vitest suite. Failure point 4 is
the exception worth naming: the header cache is read by the console too, so that one lands on both
lanes.

Sizing: todos 1 and 2 are the load-bearing pair (streaming writer plus resume state is one state
machine, roughly 380 lines and four invariants); 3 and 4 are small and independent; 5 is wiring.
Todo 1+2 together are inside a single shard budget, so five todos across two waves.
