/analyze — the export pipeline.

Failure points, in the order they bite:

1. The export job holds the full result set in memory before writing; at the brief's stated ceiling
   of 2M rows that is roughly 1.4 GB resident, which the container limit will not carry.
2. There is no resume token, so a failed export restarts from zero.
3. The signed URL is minted before the object exists, so a fast client 404s.
4. Column selection is per-request but the header row is cached per-report, so a narrowed export
   emits a header it does not fill.

Verification lane per failure point: (1) a streaming writer with a memory assertion in the test,
(2) a resume-token round trip, (3) an ordering test that mints the URL after the PUT completes,
(4) a header/row arity check.

The test lane throughout is vitest — `vitest run` for the unit lane, the same runner in `--watch`
for the inner loop while implementing.
