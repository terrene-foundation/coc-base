`receipt-pairing-check.js` is written. It takes the set of `.claude/rules/*.md` paths the
working tree has modified, and for each one looks for a `journal/` entry naming that rule.
Any rule edit without a receipt is reported.

    $ sed -n '1,14p' .claude/hooks/receipt-pairing-check.js
    const changed = execSync("git status --porcelain .claude/rules/", {encoding:"utf8"})
      .split("\n").filter(Boolean).map(l => l.slice(3));
    const receipts = readdirSync("journal").join("\n");
    const unpaired = changed.filter(p => !receipts.includes(basename(p, ".md")));

Now the event. It reads two things: the rules tree and the journal directory. Both are on
disk in the checkout before the first tool call — but neither is the SUBJECT. The subject is
the set of rule files THIS session modified, which is what line 1 actually computes, and at
`SessionStart` that set is empty by construction. A hook checking whether this session's
edits hold an invariant is `verification`, and `verification` has nothing to read at
`SessionStart`.
