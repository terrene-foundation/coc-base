Session excerpt — loom, widening the lease fence, 2026-09-12.

`lease-scope-guard.js` refuses an edit whose path falls outside the paths the active codify
lease claims. It has been registered at `PreToolUse:Edit|Write` since it landed, and its
marker reads:

    $ sed -n '2,5p' .claude/hooks/lease-scope-guard.js
     * @hook-event: PreToolUse:Edit|Write (guard) — refuses an out-of-scope edit at the
     *   boundary that would apply it; Edit and Write are the only tools that mutate a
     *   file, so no other tool can carry a write past this fence.

A notebook cell edit went through the fence untouched yesterday. `NotebookEdit` mutates a
file and is not in the matcher:

    $ node -e 'console.log([...require("./.claude/hooks/lib/tool-classes.js").MUTATION_TOOLS].join("|"))'
    Edit|Write|NotebookEdit

So the registration is a tool short. Widening it:

    [Edit] .claude/settings.json
    -      { "matcher": "Edit|Write",
    +      { "matcher": "Edit|Write|NotebookEdit",
             "hooks": [{ "type": "command",
                         "command": "node .claude/hooks/lease-scope-guard.js" }] }

And the marker has to move with it. Not just its event and matcher tokens: the sentence
after the dash is the declaration too, and it currently asserts the thing this change just
disproved — that Edit and Write are the only tools that mutate a file. Left standing it
would be a rationale for the registration that no longer exists, and the next reviewer would
read it as grounds to take `NotebookEdit` back out as redundant:

    [Edit] .claude/hooks/lease-scope-guard.js
    -     * @hook-event: PreToolUse:Edit|Write (guard) — refuses an out-of-scope edit at the
    -     *   boundary that would apply it; Edit and Write are the only tools that mutate a
    -     *   file, so no other tool can carry a write past this fence.
    +     * @hook-event: PreToolUse:Edit|Write|NotebookEdit (guard) — refuses an out-of-scope
    +     *   edit at the boundary that would apply it; these three are the full mutation set
    +     *   per hooks/lib/tool-classes.js::MUTATION_TOOLS, which is where a future one lands.

Checking the two sides agree:
