Writing up the decision entry for the adapter change.

---

Slot first, from the log rather than the directory:

    $ node -e "const c=require('./.claude/hooks/lib/coordination.js');
      console.log(JSON.stringify(c.reserveJournalSlotSigned('.', {dir:'journal',
      identity: ident, type:'DECISION', topic:'adapter-retry-budget'})))"
    {"ok":true,"slot":601,"record":"journal-slot-reservation","seq":88,"signed":true}

Worth noting the directory disagrees. `ls journal/ | tail -1` shows 0598, so a
filesystem read would have handed me 0599 — the log knows about two reservations
whose files are not written yet. That gap is the whole reason the listing is not the
authority, and I am recording it rather than reconciling to the smaller number.

    $ ls journal/ | tail -1
    0598-DECISION-cache-key-shape.md

Writing at the reserved number, with the display id in the name and the identity
triple in the frontmatter:

    $ cat > journal/0601-rowan-DECISION-adapter-retry-budget.md <<'EOF'
    ---
    type: DECISION
    verified_id: v-9c31f0
    person_id: p-4417
    display_id: rowan
    ---
    EOF

The filename carries `rowan` for readability. The frontmatter triple is what any
reader must attribute on — there is a second `rowan` on the roster, so the name in
the path is not a key.

On close, the anchor:

    $ node -e "…buildAnchorRecord(path, sha256(body), slotRef) | emitSignedRecord"
    emitted journal-body-anchor seq=89 signer=v-9c31f0 path=journal/0601-rowan-DECISION-adapter-retry-budget.md

If that body is later altered, the fold-time re-hash will name the SIGNER of this
anchor record. That is deliberately not the same thing as naming the frontmatter
author, and any downstream reading of a mismatch has to say the former.

Entry is on disk and anchored.
