# destination-local-json — destination-mode `.local.json` scan-on

Per `rules/cc-artifacts.md` Rule 9 + `rules/hook-output-discipline.md` MUST-4. Pins the issue #352 destination-mode fix — a `.local.json` that reaches a sync destination IS the disclosure event the scanner exists to catch, so it must be scanned there. The rule no longer keys on the scan root: the old `REPO_ROOT_ACTIVE === REPO_ROOT` proxy (skip every `.local.json` in an in-place scan, scan every one under `--root`) is gone, and `isExcluded` now skips a `*.local.json` only when `isGitTracked` reports it untracked (`.claude/bin/scan-synced-disclosure.mjs:996-996::isGitTracked`). That answer is the same at a source root (in-place scan) and a destination root (`--root`): a git-tracked file (committed or staged) is SCANNED; an untracked one is SKIPPED only when the scan root sits inside a git work tree and `git ls-files --error-unmatch` exits 1 for it, which is how a loom-source scan keeps skipping the untracked per-operator companions; a root outside any work tree, or an inconclusive git probe, fails closed to SCANNED (`.claude/bin/scan-synced-disclosure.mjs:645-662::isGitTracked`). THIS case takes that last, no-git branch, not the tracked one: the runner copies it into a fresh `mkdtemp` root under the OS temp directory, which is not a git work tree, and scans it with `--root` (`.claude/audit-fixtures/scan-synced-disclosure/run.mjs:1873-1902::scanRoot`), so it reds if the rule turns into an unconditional skip or the no-git probe fails open, but it passes unchanged under the old proxy. The tracked-versus-untracked split is pinned instead by the runner's in-place scenario `local-json-tracked-flagged-untracked-skipped-in-place` (`.claude/audit-fixtures/scan-synced-disclosure/run.mjs:2138-2180`).
