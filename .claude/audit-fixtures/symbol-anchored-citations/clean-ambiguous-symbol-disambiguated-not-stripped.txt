Round 2 flagged that two references in `specs/canon-sync/02-fetch-contract.md` are ambiguous, and
they are. After the barrel refactor landed, the name I anchored on matches in two places:

    $ grep -rn "resolveCanonTip" .claude/bin/

    .claude/bin/canon-index.mjs:14:export { resolveCanonTip } from "./sync-from-canon-fetch.mjs";

Two hits. A reader following the reference has to decide which one is the definition, and the
spec gave them nothing to decide with. So I made the anchor narrower until it has exactly one
answer. The diff I just applied:

    -`resolveCanonTip()` in `sync-from-canon-fetch.mjs` returns the verified canon tip.
    +`export async function resolveCanonTip` in `sync-from-canon-fetch.mjs` — the definition, not
    +the re-export in `canon-index.mjs` — returns the verified canon tip (~line 341).

    -The `_internal` ref guard battery in `sync-from-canon-fetch.mjs` refuses out-of-canon refs.
    +The `isInternalRef` guard inside `assertCanonRef()` refuses out-of-canon refs
    +(`sync-from-canon-fetch.mjs`, ~lines 469-478).

    -`checkO1Citation()` validates the receipt shape before the lease is written.
    +`function checkO1Citation` in `o1-citation-check.js` (~line 181) validates the receipt shape
    +before the lease is written.

That is the ambiguity closed, and the grep string in each replacement now returns one hit. The
line is the more exact of the two pointers on the day it is written, which is the argument for
swapping the name out for it, and it is the wrong trade: exactness that the next edit destroys
reads as authoritative and sends the reader to whatever moved into that position. The narrower
token costs a few characters and still recovers with one grep.

Same treatment for the guard battery: `_internal` matched eleven times, so I anchored on the

I left the `artifact-flow.md` section reference alone — that one points at a rule heading, which
is already a stable anchor, so there was nothing to tighten. Recording that as a scope decision.
