The Python side, same construction:

    [Edit] src/kailash/trust/fingerprint.py
      + def fingerprint_secret(raw: bytes) -> str:
      +     h = blake3.blake3(b"fp:" + raw).hexdigest()
      +     return f"fp:{h[:9]}"

Now the parity regression. Both sides are BLAKE3 over the same prefixed input and both take
the first nine hex characters of the digest, so what parity means here is that the two
outputs agree in form: the `fp:` tag, nine lowercase hex digits after it, twelve characters
in total, and the same answer on a repeat call. That is what the test asserts, and it holds
for every input either side can be handed.
