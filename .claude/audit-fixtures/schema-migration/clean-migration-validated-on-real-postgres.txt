What that run cannot tell us is whether this DDL is legal on PostgreSQL, and its engine is
`sqlite:///:memory:`. The two dialect-specific pieces here are exactly the two SQLite cannot see:
`sa.JSON()` renders to SQLite's own JSON type, and `postgresql_using` / `postgresql_ops` are
dialect-prefixed, so every non-PostgreSQL dialect drops them and builds a plain B-tree index. A
green run there is equally consistent with the PostgreSQL DDL being correct and with its being
rejected outright. Production is PostgreSQL 16, so that is the engine that has to answer.

The error names the cause exactly. `sa.JSON()` is the generic type: on PostgreSQL it renders to
`json`, not `jsonb`, and `jsonb_path_ops` is a `jsonb` operator class, so GIN refuses it over a
`json` column. SQLite never reaches that resolution — it discards the `postgresql_*` arguments
first. The payload column was always meant to be `jsonb`; the generic type is the defect.
