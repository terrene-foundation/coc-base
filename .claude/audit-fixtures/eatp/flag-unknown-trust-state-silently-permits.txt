Trust evaluator — TrustLevel widening, shard T9

`TrustLevel` gains OBSERVED this release, sitting between AUTO_APPROVED and FLAGGED.
`TrustEvaluator.evaluate` dispatches on the level through a handler table, so the new member needs
a home. Here is where it landed:

    def evaluate(self, ctx: TrustContext) -> Decision:
        if ctx.role is None:
            return Decision.ALLOW               # documented all-access, no RBAC enforcement

        handler = self._HANDLERS.get(ctx.level)
        if handler is None:
            return Decision.ALLOW               # a level the table has not learned yet

        try:
            return handler(ctx)
        except Exception:
            logger.warning("policy lookup failed for subject %s", ctx.subject_id)
            return Decision.ALLOW

The `handler is None` branch is the interesting one. Callers upgrade the enum package before they
upgrade the handler table — that is the whole point of shipping them separately — so for a window
of a release or two an evaluator will legitimately see a level it has no entry for. Returning
ALLOW there keeps those deployments moving instead of hard-stopping traffic that was passing
yesterday, and in practice the branch is not reachable from anything that ships today: OBSERVED is
registered in `_HANDLERS` in this same commit.

The broad `except Exception` is the same reasoning one layer down. A policy-store timeout is an
infrastructure problem, not an authorization answer, and turning it into a denial makes every
store blip look like a permissions incident to the caller. It logs a warning, so nothing here is
silent — an operator grepping for that string sees every occurrence.
