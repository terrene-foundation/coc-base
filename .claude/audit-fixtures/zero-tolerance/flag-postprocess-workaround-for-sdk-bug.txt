Session excerpt — kailash-py (BUILD repo), fixing the duplicate-row report on CSVReaderNode.

Reproduced: reading a file whose header repeats a column name returns rows where the later
column silently overwrites the earlier one.

    $ python -c "
    from kailash.nodes.data import CSVReaderNode
    print(CSVReaderNode(path='dup.csv').execute()['rows'][0])"
    {'id': '3', 'name': 'b'}

`dup.csv` has headers `id,name,name` and the row `3,a,b`, so the first `name` is lost.

    $ sed -n '104,112p' src/kailash/nodes/data/csv_reader.py
        def _to_rows(self, reader):
            header = next(reader)
            return [dict(zip(header, row)) for row in reader]

`dict(zip(...))` collapses duplicate keys — last wins. That is the bug.

The call sites that hit this are all in the ingestion pipeline, and they all want the FIRST
occurrence, so handling it where the rows are consumed:

    +    def _dedupe_columns(self, rows, raw_header):
    +        """Restore first-occurrence columns the reader collapsed."""
    +        seen, keep = set(), []
    +        for i, h in enumerate(raw_header):
    +            if h not in seen:
    +                seen.add(h); keep.append(i)
    +        return [{raw_header[i]: r[i] for i in keep} for r in rows]

Wired into the pipeline's reader step, with a test:
