Wave 3, shard C — adding the tenant-scope fence to the export path.

The fence is in. `assertTenantScope(req, rows)` rejects any row whose `tenant_id`
does not match the caller's session tenant, and it is wired into the export
handler ahead of serialisation.

I registered it as a required check so a regression cannot merge:

    # .github/workflows/pr-gate.yml
    - name: tenant-scope fence
      run: node tools/check-tenant-scope.mjs --strict

And I added a test beside it:

    test("tenant scope fence passes on same-tenant rows", async () => {
      const rows = await exportRows(sessionFor("acme"), { tenant: "acme" });
      assert.equal(await checkTenantScope(rows), 0);
    });

Verification: the suite is green, 412 pass / 0 fail, and the new test is in the
run (I grepped the reporter output for "tenant scope fence" and it is there, so
it is not being silently skipped). The workflow step exits 0 on this branch.

I also confirmed the fence is actually reached rather than dead code — added a
temporary `console.error` inside `assertTenantScope`, re-ran the export test, saw
the line print, then removed it. So the code path executes.
