# `deferral-variant-scope` audit fixtures

Pins the **rule-corpus scope** of the Phase-2 deferral gate
(`.claude/bin/phase2-deferral-integrity.mjs`) — which directories it reads, and
which declared `rule` paths and registry keys it admits.

Run:

```bash
node .claude/audit-fixtures/deferral-variant-scope/run.mjs
```

Registered in `.claude/test-harness/ci-audit-fixtures.json` (`mode: run`). The
case floor is declared **there and only there**; this file deliberately does not
restate it. A count restated in prose and not coupled to the registry is the
drift `.claude/test-harness/tests/audit-fixture-prose-count-coupling.test.mjs`
exists to catch — and the dangerous repair direction is LOWERING the CI floor to
match stale prose. Read the number from the registry.

## The defect — two sides, and they are not the same bug

**Corpus side (silent).** Pass 2 of the gate reconciles corpus → registry: every
Phase-2 clause inside a Trust Posture Wiring block must be registered or
explicitly acknowledged. It enumerated ONE directory — `readdirSync(rulesDir)`,
non-recursive, canon only. A rule under `.claude/variants/<v>/rules/` was never
read, so the unregistered-deferral error could not fire for it **at all**. Not
"fired and was dismissed" — never reached. Two such clauses exist on the live
corpus today (`.claude/variants/rs/rules/build-speed.md`,
`.claude/variants/rs/rules/canon-incorporation.md`) and the gate is green on
both. Silence from an instrument that never looked is not a clean result
(`instrument-discipline.md` MUST-3(a)).

**Registry side (loud, but a dead end).** Two `startsWith(".claude/rules/")`
guards refused any declaration whose `rule` named a variant path. So the corpus
side could not SEE a variant deferral and the registry side would not LET you
declare one. Both exits closed — which is why an operator who noticed the gap
had no way around it.

**A third fence sat behind those two.** The registry key class `[a-z0-9.-]+`
excludes `/`, so a variant key could carry no lane segment — and without one, a
variant row's key is byte-identical to its canon sibling's and the two collide
in a flat object. Widening the path predicate alone would have produced a
registry that accepts a variant `rule` but cannot NAME it distinctly: a half-fix
that reads as a whole one. `keygrammar/silent-same-basename-canon-and-variant-rows-coexist`
is that case made runnable — `security.md` exists in both trees on the live
corpus.

## What the fixtures pin

| Subject                           | Cases                                                                                                                                                                                                                          |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ruleCorpusRoots`                 | canon first; every existing variant `rules/` dir; sorted **by variant name**; a variant with no `rules/` subdir excluded; no `variants/` tree at all; labels repo-relative; dirs absolute and inside the repo                  |
| `isRuleCorpusPath`                | canon and variant accepted (incl. hyphenated and digit-bearing lane names); agents / skills / docs / repo-root / nested / non-markdown / `..` / absolute / `./`-prefixed refused; non-string inputs refused rather than thrown |
| `expectedRuleForKey`              | canon and lane-qualified keys; hyphenated clause slugs; dotted basenames; every derived path is itself admissible                                                                                                              |
| `checkPhase2Deferrals` end to end | corpus enumeration, path admission, key↔rule coherence, quote binding across the boundary, and the same-basename collision                                                                                                     |

## Bipolar, and the control every silence carries

Each side gets a pole that must FIRE and a pole that must stay SILENT, and the
two differ in exactly one property — the rule's location, the declaration's
path, or the key's lane segment. The rule BODY is generated by one function, so
no pole pair can differ by content.

A check asserting an error is ABSENT passes identically when the whole
instrument is dead. So every silent pole runs a canon-side rule through the SAME
repo, the SAME checker call and the SAME error list and asserts that one DOES
fire (`corpus/control-canon-still-FIRES-while-variant-is-silent`,
`corpus/control-same-body-at-corpus-depth-FIRES`,
`registry/control-canon-path-is-accepted-and-green`). If a control goes quiet,
the silence is the instrument and the case says so by name.

`roots/variants-are-not-sorted-by-full-label-string` is the negative half of the
sort pin, and it is not pedantry: `-` (0x2D) sorts before `/` (0x2F), so a
label-string sort puts `py-codex` ahead of `py` and splits a lane family. The
expected order is a literal array rather than a re-derived `.sort()`, because
computing the expectation with the same operation the subject uses is a
self-derived oracle (`evidence-first-claims.md` MUST-5).

## Mutation record

A green suite over a landed behaviour change is not evidence until a mutation
REDs it (`instrument-discipline.md` MUST-5). Six mutations were applied to a
**copy** of the checker outside the repo. Each emitted a reach marker that was
confirmed in the run output **before** the result was read, so no red-set was
banked from a mutation that never executed. No red-set was empty.

| #   | Mutation                                 | Red                                                         |
| --- | ---------------------------------------- | ----------------------------------------------------------- |
| M1  | `ruleCorpusRoots` returns canon alone    | 9 — every variant-enumeration case                          |
| M2  | `RULE_CORPUS_PATH_RE` narrowed to canon  | 18 — incl. `roots/enumerator-and-admission-predicate-agree` |
| M3  | `DEFERRAL_KEY_RE` reverted to lane-less  | 9 — the key-grammar family                                  |
| M4  | `isRuleCorpusPath` returns `true` always | 25 — every refusal pole                                     |
| M5  | variant sort reversed                    | 1 — the sort pin only                                       |
| M6  | `rules/`-exists guard dropped            | 3 — incl. two `block/ABORTED-BY-THROW`                      |
| K1  | `/g` flag added to `DEFERRAL_KEY_RE`     | 9 — incl. all four end-to-end coherence cases               |
| K2  | `/` admitted into the key basename class | 5 — the rule-path-as-key family                             |
| K3  | key lane class made case-insensitive     | 1 — `keyre/refuses-uppercase-lane`                          |

**K1 is the one to read.** `DEFERRAL_KEY_RE` stopped being private and is now
shared with the deferral-request / accept path. Adding `/g` makes `.test()`
**stateful** — `lastIndex` advances, so two callers alternating on the same
object get answers that depend on call ORDER rather than on the key. The
measured blast radius is not confined to the grammar's own poles: it reds all
four `keygrammar/fires-*` cases, meaning the coherence fence starts silently
accepting keys it should reject. `keyre/carries-no-g-flag-so-it-is-stateless-across-callers`
and `keyre/repeated-tests-of-one-key-agree` exist to catch exactly that edit,
because a stateful shared matcher is a non-discriminating instrument by
construction.

M6 also found a defect in **this runner**: the unguarded `readdirSync` throws out
of the gate, and a bare block layout let that one throw kill every later case,
so the red-set read as a single line instead of the cases the mutation actually
broke. Case blocks now run under `group()`, which records a throw as an
explicit named FAIL and keeps counting. That is not a swallow — the process
still exits non-zero — and it matters because a suite that stops counting on the
first throw under-reports and then trips its own `min_cases` floor for a reason
unrelated to the drop the floor exists to catch.

## Scope limit — stated plainly

These fixtures pin predicates and one end-to-end reconciliation on synthetic
trees. They do **not** establish that the gate blocks a merge: that is branch
protection, which is mutable repo state no fixture here reads. Query it before
concluding anything, and use `has()` rather than the object-construction form,
which yields `null` for a missing key and so cannot tell ABSENT from
PRESENT-AND-NULL.

Nothing here reads the live registry or the live rules corpus, and the clock is
injected. Editing either changes the live gate and never silently rewrites what
these fixtures assert.
