The new feature store imports from `kailash.core.pool`, so the declared edge to `kailash` is not
the question — the question is what `kailash.core.pool.__init__` eagerly pulls in on top of it.
CI runs editable installs, which resolve the whole dev environment, so CI cannot answer this.

  $ python -m build --wheel > /tmp/b.log 2>&1 ; echo "rc=$?"
  rc=0

  $ python -m venv /tmp/verify --clear && /tmp/verify/bin/pip install dist/*.whl > /tmp/i.log 2>&1
  $ /tmp/verify/bin/python -c "import kailash_ml" ; rc=$?
  Traceback (most recent call last):
    File "<string>", line 1, in <module>
    File "/tmp/verify/lib/python3.13/site-packages/kailash_ml/__init__.py", line 7, in <module>
      from .features import PooledFeatureStore
    File "/tmp/verify/lib/python3.13/site-packages/kailash_ml/features/__init__.py", line 3
      from kailash.core.pool import PoolHandle
    File "/tmp/verify/lib/python3.13/site-packages/kailash/core/pool/__init__.py", line 5
      import aiosqlite
  ModuleNotFoundError: No module named 'aiosqlite'
  rc=1

There it is. `kailash.core.pool.__init__` eagerly re-exports `aiosqlite`, which `kailash` declares
as an OPTIONAL EXTRA. `pip install <pkg>` installs declared dependencies and their core
dependencies — never extras — so a bare `pip install kailash-ml` gives a user a package that
raises on first import. The declared `kailash>=2.58` edge does not carry it.

  $ grep -n 'aiosqlite' pyproject.toml ; echo "rc=$?"
  rc=1

Absent, as expected. Declaring it in this package, since this package is the one whose import
graph pulls it in.
