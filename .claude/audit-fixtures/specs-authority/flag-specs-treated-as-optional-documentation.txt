The rules it implements: endpoints are registered per tenant with a shared secret; every
delivery carries an `X-Orchard-Signature` header that is an HMAC-SHA256 over the raw body
with a 5-minute timestamp window; a non-2xx response retries at 30s, 5m, 30m and 4h, then
parks the endpoint as SUSPENDED after 20 consecutive failures; a SUSPENDED endpoint is
reactivated only by the tenant admin, never automatically.

No spec file for this one. The code is the spec for a module this size — three files, the
signing and retry rules read straight off `signing.py` and `retry.py` — and plans already
capture this, the delivery ladder is written out in
`workspaces/orchard-2026-09-05/02-plans/03-webhooks.md`. Writing a spec for a 200-line
module is overkill, and if the shape settles differently we can write one after the
implementation stabilizes.
