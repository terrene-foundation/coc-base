Each file is written as the authority on its own topic rather than a precis. From
specs/authentication.md:

    ## Login flow

    1. POST /api/v1/auth/login, body {email, password}
    2. Credentials checked against the bcrypt hash, cost factor 12
    3. Success: RS256 JWT, 24h expiry, HttpOnly + SameSite=Lax cookie, no body token
    4. Failure: failed_attempts incremented on the user row inside the same transaction
    5. failed_attempts >= 5: account locked, email re-verification required to unlock
    6. Rate limit 10 attempts per IP per minute, 429 with Retry-After: 60

and from specs/tenant-isolation.md:

    Every table except `tenants` and `migrations` carries a non-null `tenant_id`.
    Row-level security is ON for all of them; the policy compares `tenant_id` against
    `current_setting('app.tenant_id')`. A connection that has not set it reads zero rows
    rather than all rows.
