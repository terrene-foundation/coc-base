# detectStateFileMutation audit fixtures

Per `rules/cc-artifacts.md` Rule 9 + `rules/hook-output-discipline.md` MUST-4. Each fixture pins one scope-restriction predicate `detectStateFileMutation(command, pathRx)` relies on. Inputs are bash command strings (paired with a path regex the caller passes — `/posture\.json/` for most, `/coordination-log\.jsonl/` for `*coord*` fixtures); expected outputs are the JSON returned by the detector — `null` (no flag) or a structural detection object naming the layer (1: redirect/tee/sed-i, 2: cp/mv/chmod/truncate, 3: interpreter WRITE body).

**Executable runner:** `test.mjs` (this dir) iterates EVERY `<name>.txt`/`<name>.expected` pair in this dir AND in `../detectStateFileMutationSegmentAware/`, plus a ReDoS regression (a 50k-char adversarial near-match completes <100ms). Run: `node .claude/audit-fixtures/violation-patterns/detectStateFileMutation/test.mjs`.

**#1292 read-vs-write gate.** Layer 3 is a MUTATION detector: both Layer-3 branches are gated on the positive write-allowlist `STATE_INTERP_WRITE_RX`, so an interpreter body that only READS the protected path (`readFileSync`, `python3 -m json.tool <state>`, `json.load(open(p))`, `list.append()`) carries no write token and PASSES; only an actual write vector AND the path flags. The prior `flag-python-m-flag` fixture (which expected a `-m json.tool` READ to flag) was REMOVED and replaced by `clean-python-m-json-tool` — the read now correctly passes.

**#1337 — shared predicate, broadened vectors, segment scope.** Three changes, each with fixtures below:

1. **ONE shared predicate.** Both Layer-3 branches now call `hasInterpreterWriteSignal()` instead of each restating the regex test (`security.md` § Enforcement-Surface Parity — a vector added to one branch could otherwise be silently absent from the other).
2. **Broadened write vectors (under-block closure).** The #1292 allowlist enumerated ~8 vectors, leaving most of each interpreter's real mutation surface un-gated — measured against the real hook, 37 mutation payloads across node/python/ruby/perl returned exit 0. The sources are now grouped BY SURFACE in `STATE_INTERP_WRITE_SOURCES` (mode/open-flags · node fs APIs · destructive ops · python · ruby · shell-out · dynamic-dispatch/obfuscation), plus `STATE_INTERP_INPLACE_RX` for the perl/ruby `-i` ARGV flag. **Every group has at least one `flag-*` fixture AND, where a sibling read could be confused with it, a paired `clean-*` fixture** (e.g. `clean-ruby-file-open-read` is why `File.open`/`File.new` are mode-gated rather than bareword-listed; `clean-fs-bracket-read-no-concat` is why the obfuscation signal keys on `+`-concatenation, not on bracket access).
3. **Segment scope.** The fallback tests the interpreter-led SEGMENT when nothing outside it can contribute to the interpreter's argv (no heredoc, no `$(…)`/backtick/`$'…'`, no `$`); otherwise the whole-command scope is retained unchanged, fail-closed. `flag-assembled-body-dollar-var` and `flag-heredoc-write-text-body` pin the fail-closed half; `clean-read-sibling-line-*` pin the false-positive half.

Branches with no `<name>.txt` representation — the `splitShellSegments` options (`newlineSeparates` / `withOffsets`, both default-OFF so pre-#1337 callers are byte-identical) and `hasInterpreterWriteSignal` itself — are pinned by unit assertions at the end of `test.mjs`.
