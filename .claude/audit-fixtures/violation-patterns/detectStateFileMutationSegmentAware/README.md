# detectStateFileMutationSegmentAware audit fixtures

Per `rules/cc-artifacts.md` Rule 9 + `rules/hook-output-discipline.md` MUST-4. Each fixture pins one scope-restriction predicate `detectStateFileMutationSegmentAware(command, pathRx)` (and the `detectStateFileMutation` Layer-1 matcher it calls) relies on. Inputs are bash command strings (paired with a path regex the caller passes — typically the trust-posture `STATE_PATH_RX`); expected outputs are the JSON returned by the detector — `null` (no flag) or a structural detection object naming the layer (1: redirect/tee/sed-i, 2: cp/mv/rm/chmod, 3: interpreter -c body).

The detector wraps `detectStateFileMutation` with quote-aware SEGMENT splitting so the `git commit … -m/-F` body exception applies PER SEGMENT. For a commit segment it MASKS the quoted message body (rather than skipping) before detection; because `$(…)`/backtick command-substitution AND bash-5.3 `${ …;}`/`${| …;}` funsubs EXECUTE inside double quotes, and `$'…'` ANSI-C quoting desyncs the quote scan, a commit segment containing any of those (`EXECUTES_INSIDE_QUOTES_RX`) additionally fails closed by re-scanning the RAW segment. The commit-body recognizer accepts `-m`/attached-`-m`/`-am`/`--message`/`-F`/`--file` forms. The Layer-1 redirect matcher recognizes every file-writing form — `>`, `>>`, `>|` (force-clobber), `&>`, `&>>`, and fd-prefixed `N>`/`N>>`/`N>|` — while excluding fd-dups (`2>&1`, `>&2`). Closes issue #745 Evasion 1, the redirect-on-commit sibling, and the redteam-surfaced F1 (command-sub in body) / F2 (ANSI-C desync) / F3 (`-am` false positive) / Finding-1 (redirect-operator coverage) / Finding-2 (funsub).

**#1292 documentation-body masking.** The same mask-not-skip discipline is extended (`DOC_BODY_WRAPPER_RX`) to the other prose-carrying wrappers: `gh issue/pr create|edit --body`/`--body-file`, `echo`, `printf`. A state-write EXAMPLE quoted as DATA inside such a wrapper (an issue body / echoed doc) does NOT fire, while a REAL interpreter execution, a real unquoted redirect on the wrapper segment, and a `$(…)` command-substitution write (fail-closed raw re-scan) still do. These commands never mutate a protected LOCAL state file themselves, so masking their quoted body can only REMOVE tokens, never synthesize a hit. Detector source: `.claude/hooks/lib/violation-patterns.js::detectStateFileMutationSegmentAware` + `::detectStateFileMutation`.

## #1363 — operand vs prose (each case-name IS the finding id)

The detector matched prose INSIDE command arguments, so writing an accurate bug
report about a state file tripped the guard protecting that file — self-sealing.
Two independent root causes, both measured at loom HEAD before the fix.

**Defect 2 — the executing-construct test was not quote-aware.** `$(`, a
backtick, `$'` and `${ ` were matched ANYWHERE in the text, so a
markdown-backticked prose body fail-closed into a RAW re-scan of the prose and
BLOCKED. Under POSIX shell quoting, **inside a single-quoted span every byte is
literal** — nothing there can execute. `hasActiveExecutingConstruct` now fires
only where the shell would actually act (unquoted / double-quoted), with `\$` /
`` \` `` honored as escapes. Fail-closed cases are unchanged.

**Defect 1 — the quoted-body mask was allowlisted to too few carriers.** Only
`git commit` + `gh (issue|pr) create|edit --body` + `echo`/`printf` rode the
mask; `git tag -m`, `git notes add -m`, `gh release --notes`, `gh gist --desc`,
`gh pr comment|review --body` went to the raw scan. `PROSE_CARRIER_RX` is a
POSITIVE allowlist on BOTH axes — an allowlisted COMMAND paired with a flag that
means "human message" FOR THAT COMMAND (`cc-artifacts.md` Rule 10). Two axes are
what make `-m` safe to honor: `git revert -m 2` (mainline parent number) and
`python3 -m <module>` (execution) are excluded by construction.

Every `clean-*` row below FLAGGED before the fix and is clean after; every
`flag-*` row is identical before and after (fail-closed behavior PRESERVED).
