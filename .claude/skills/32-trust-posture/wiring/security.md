# security — governance bookkeeping

**This file carries the Trust-Posture Wiring, the rule-graph cross-references and the
Origin record for `.claude/rules/security.md`. It is NOT a rule and states no new
obligation — every MUST and MUST NOT token below RESTATES a clause that lives in the
rule, quoted so the Wiring fields can name what they bind.**

**Why it is here.** Claude Code injects every `.md` under `.claude/rules/` recursively at
launch; the skills tree is not injected. Governance bookkeeping is read by gate-review and
by the validators, never acted on mid-turn, so every session was paying for it. This tree
also SHIPS (`skills/32-trust-posture/**` is a distribution tier) and is already on the
self-referential allowlist, so consumers keep their Wiring and edits here still fire the
Tier-1 gate.

- **Detection mechanism:** Phase 1 (manual, gate-review) — for any field promoted to a fail-closed authorization control at an eval surface, enumerate ALL validators referencing the control's field/type, then grep each re-registration / monotonic-tightening validator for the field name (absence is a finding); run by security-reviewer at `/implement` + cc-architect at `/codify`. **Probes: REGISTERED — `.claude/test-harness/probes/security.probes.json`**, 10 rows in 5 bipolar `pair_id` pairs, with candidate fixtures + answer-key sidecars at `.claude/audit-fixtures/security/`. Four FIRING pairs — the derived `## MUST NOT` clause, plus the `## Parameterized Queries`, `## Credential Decode Helpers` and THIS `## Enforcement-Surface Parity` clause, each carrying BOTH a violation and a compliant pole — and one meta-compliance pair. The rule derives only `MUST-NOT` mechanically (`deriveClauses` shape `must-not-only`), so the remaining clause ids are hand-listed in `clause-coverage-baseline.json`, the `git.md` named-section precedent. Registration buys DISPATCHABILITY, never automatic execution: no workflow invokes `coc-probe-dispatch.mjs`, and the loom↔csq boundary keeps CI LLM-free, so a green CI run is NEVER evidence these probes passed — they execute only when an orchestrator dispatches `/test-harness-probe --artifacts` at gate-review. **Phase 2 is RETIRED for § Enforcement-Surface Parity, not pending (2026-09-13): no hook detector will EVER be built, and no structural audit fixtures are owed.** This clause turns on two facts, and NEITHER is carried by any argv token, AST node, parsed-document field, filesystem fact or git-object fact at tool-call time. The first is whether a change PROMOTED a field to a fail-closed AUTHORIZATION control — a judgment about what the field now MEANS in the trust model, not about any syntax it acquired; the originating incident (#1456) promoted an already-declared `clearance_required` field whose declaration did not change at all, so a diff-shaped detector had nothing to see. The second is whether EVERY INDEPENDENT validation surface learned it, and that enumeration is declared NOWHERE: the Phase-1 procedure above is "enumerate ALL validators referencing the control's field/type", a search whose COMPLETENESS no registry certifies, so a detector could never know whether the surface it failed to find was absent or merely unlisted — the non-discriminating instrument `instrument-discipline.md` MUST-1 blocks as evidence. The only mechanizable residue is a grep for a field name, which fires identically on the compliant and the violating tree. Booking a detector on that signal is teeth that cannot arrive, which `hook-output-discipline.md` MUST-5(b) forbids and `rule-authoring.md` MUST NOT names. **Gate-review IS the enforcement layer here, permanently**, paired with the registered `Enforcement-Surface Parity` probe pole above. The former forward-pointer to a not-to-be-built fixture directory is withdrawn WITH the deferral — from this body, and from `validate-xref-integrity.mjs::SANCTIONED_DEFERRED_FIXTURES`, whose carve-out is DELETED rather than left standing so that the next genuinely-dangling reference at that slug is flagged loudly instead of absorbed.
- **Violation scope:** the Enforcement-Surface-Parity clause ONLY (clause-scoped); pre-existing grandfathered `security.md` sections stay exempt until each is itself `/codify`-touched.
