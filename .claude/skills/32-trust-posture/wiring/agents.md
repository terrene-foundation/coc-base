# agents — governance bookkeeping

**This file carries the Trust-Posture Wiring, the rule-graph cross-references and the
Origin record for `.claude/rules/agents.md`. It is NOT a rule and states no new
obligation — every MUST and MUST NOT token below RESTATES a clause that lives in the
rule, quoted so the Wiring fields can name what they bind.**

**Why it is here.** Claude Code injects every `.md` under `.claude/rules/` recursively at
launch; the skills tree is not injected. Governance bookkeeping is read by gate-review and
by the validators, never acted on mid-turn, so every session was paying for it. This tree
also SHIPS (`skills/32-trust-posture/**` is a distribution tier) and is already on the
self-referential allowlist, so consumers keep their Wiring and edits here still fire the
Tier-1 gate.

### Clause-scoped wiring — A Dispatched Agent's Result Is Not Received Until It Is DELIVERED (added 2026-08-16)

Applies to the **§ Agent-Result-Delivery** clause ONLY (USE-template origination 2026-08-13; DELIVERY GATE extended + RECOVERY half added 2026-08-14 after the class recurred twice in one session; landed at loom 2026-08-16 via `/sync-from-use` Gate-1 placement); ships canonical-8-field-compliant. Grandfather + precedent: guide § Clause-Scoped Wiring Precedent.

- **Severity:** `halt-and-report` at gate-review (reviewer at `/implement` + cc-architect at `/codify` confirm every relied-on payload STATED A RESULT rather than announcing work to come — "returned a payload" is the test this clause declares too weak and does NOT satisfy the gate — that no `name` was paired with the task-return-contract instruction, and that any resume stayed inside the (3) bounds: one per lane, self-assigned sub-goal only, UNRESOLVED items carried as open findings); `halt-and-report` at the hook layer, which is what the SHIPPED detector already emits — `hooks/lib/dispatch-contract.js::detectNamedDispatchWithoutDelivery` returns `severity: "halt-and-report"`, registered on the `PreToolUse` `Task|Agent` matcher. `hook-output-discipline.md` MUST-2 bars **`block`** on lexical evidence and NOTHING MORE, so the ceiling is `block`, NOT `advisory`. In-corpus precedent for `halt-and-report` on a lexical predicate, reconciled with MUST-2 explicitly: `repo-scope-discipline.md` § Trust Posture Wiring. Reading MUST-2 as mandating `advisory` here would license DOWNGRADING a live trust-substrate guard, and is BLOCKED.
- **Grace period:** 7 days from clause landing at loom (2026-08-16 → 2026-08-23); the originating template windows are recorded rather than folded.
- **Cumulative posture impact:** same-class violations (a named agent dispatched under the task-subagent return contract; a lifecycle notification counted as a delivered result; a STATUS-FRAGMENT payload scored as a delivered lane; a stalled lane re-dispatched instead of resumed, discarding recoverable transcript work) route to `trust-posture.md` MUST-4 cumulative math (3× same-rule / 5× total in 30d → drop 1 posture).
- **Regression-within-grace:** GENERIC `regression_within_grace` trigger per `trust-posture.md` MUST-4 (1× = drop 1 posture) — NO dedicated key. Named deviation per Rule 8, with THIS clause's own reason (it does NOT inherit the shared one, whose "no structural signal" leg does not hold here): the loss corrupts nothing, so it does not warrant an instant-drop key. **The recoverability half of that reason holds for the SPAWN-CONTRACT part ONLY and was NOT carried over to the 2026-08-14 halves**, which is why this clause carries `halt-and-report` at gate-review rather than advisory-only.
- **Receipt requirement:** SessionStart soft-gate `[ack: agents]` IFF `posture.json::pending_verification` includes the `agents` rule_id (shared rule_id; one ack covers every clause in this file).
- **Detection mechanism:** Phase 1 (manual) — reviewer / cc-architect confirm (a) each relied-on agent returned an actual payload, not a lifecycle notification, (b) no dispatch paired a `name` with the task-return-contract instruction, and (c) every relied-on payload carries the RESULT, not a status fragment — where a fragment arrived, the lane was resumed and re-delivered, never scored nor silently re-dispatched. (c) cannot move to the shipped `PreToolUse` detector — the payload does not exist at that event; its structurally-correct home is `PostToolUse` on the delegation tools, and it stays Phase-1 because fragment-vs-terse-verdict is a semantic discrimination over prose, which `hook-output-discipline.md` MUST-2 caps at `halt-and-report` rather than `advisory`. **(c) is transcript-dependent today and therefore weakest exactly where compaction bites**; the resume transition MUST be recorded in the launch ledger (`orchestration-launch-ledger.md` MUST-1) as `in-flight → fragment → resumed → landed` so the reviewer reads a durable row rather than a session transcript. **Structural enforcement of the SPAWN-CONTRACT half ALREADY SHIPS**: `hooks/dispatch-contract-guard.js` is registered on the `PreToolUse` `Task|Agent` matcher (`settings.json`) and its `hooks/lib/dispatch-contract.js::detectNamedDispatchWithoutDelivery` emits `halt-and-report` on an addressable dispatch whose brief carries no push-delivery instruction — the exact mis-pairing part (1) forbids. **Fairness bound:** that detector attributes to `rule_id: "orchestrator-context-economy/MUST-6"`, a DIFFERENT rule, so no Phase-2 detector is booked FOR THIS CLAUSE — the coverage is inherited, not authored here. Phase-1 gate-review remains the enforcement layer for the DELIVERY-GATE and RECOVERY halves; nothing further is booked because a declared deferral is a RESIDUAL under `completion-criterion.md` MUST-6 and is not self-accepting. **Probes: REGISTERED — the dated row is GRADUATED, not renewed.** `.claude/test-harness/probes/agents.probes.json` is WRITTEN, registered in `eval-manifest.json` as a probe-only entry (`scanner: null`) and pinned in `probe-suite-integrity.test.mjs::PINNED_SUITES`; the `phase2-deferrals.json::probe_authorship_deferrals` row that dated this gap is DELETED in the same change; the `MUST-A-Dispatched-Agents-Result-Is-Not-Received-Until-firing` pair is built to that row's graduation condition and probes the DELIVERY-GATE half, the half no shipped detector reaches. Registration buys DISPATCHABILITY, never automatic execution: no workflow invokes `coc-probe-dispatch.mjs`, so a green CI run is NEVER evidence these probes passed. No audit-fixture directory is named HERE: fixtures land with the detector that owns them, and the shipped SPAWN-CONTRACT detector's fixtures are `.claude/audit-fixtures/dispatch-contract/` under `orchestrator-context-economy`, not under this clause.
- **Violation scope:** this clause ONLY — its SPAWN CONTRACT, DELIVERY GATE, and RECOVERY parts; each row names the agent and which part failed, and for a DELIVERY GATE row whether the non-delivery was a lifecycle notification or a status fragment.
